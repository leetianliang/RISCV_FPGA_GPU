The architecture direction is good and should be retained.

However Stage 003 cannot be accepted as a **feature-complete authoritative Golden sprite pipeline** yet.

The review found:

1. a major Premultiplied Alpha arithmetic error;
2. source/palette memory faults being silently ignored;
3. BLIT_EXT Clip semantics mismatching the command state;
4. BLIT_EXT axis-alignment enforcement weaker than the frozen ISA architecture;
5. insufficient command-defined SurfaceView validation;
6. tautological mutation tests that cannot fail;
7. random differential coverage far below the Stage-003 task;
8. several Stage-003 headline features verified only by fixtures generated by the implementation itself;
9. extension fault-priority / Strict behavior issues;
10. additional UV/boundary robustness issues that should be closed before Tile mode uses this Golden as its oracle.

Therefore:

> **Stage 003 = FAIL / REWORK**

This is not an architecture reset. The implementation should be hardened in a focused corrective stage.

The next execution package is:

# 3. Critical Findings

---

## C1 — Premultiplied Alpha implementation is numerically incorrect

Severity:

> **CRITICAL — Golden arithmetic is wrong**

The frozen arithmetic defines Premultiplied Alpha output RGB as:

```text
S'_c       = ColorMod(S_c)
Scontrib_c = MUL8_RN(S'_c, Aextra)

O_c =
SAT_U8(
    Scontrib_c
    +
    MUL8_RN(D_c, 255 - Aeff)
)
```

The current implementation instead effectively performs:

```text
O_c = SAT_U8(D_c + source_contribution)
```

so the destination is not attenuated by:

```text
255 - Aeff
```

This is a direct bit-exact mismatch.

There is a second error:

The general path already applies:

```text
src = color_modulate(src, PRIMARY_COLOR, COLOR_MOD_EN)
```

before blend selection.

Inside the Premult branch it then performs another:

```text
color_modulate(src, PRIMARY_COLOR, true)
```

which can apply RGB modulation a second time.

Worse, when `COLOR_MOD_EN=0`, that second call still forces modulation. Since `BlitCmdDesc::primary_color` defaults to zero, a Premult draw can incorrectly zero source RGB.

Required correction:

- preserve the sampled source before Color Mod or restructure pixel state cleanly;
- apply Color Mod RGB exactly once;
- compute `Aextra` exactly;
- compute `Aeff = MUL8_RN(Sa, Aextra)`;
- compute source contribution exactly once;
- attenuate destination by `255-Aeff`;
- match the frozen output-alpha formula;
- add independent exact-value tests.

Do not regenerate a fixture and call that proof.

---

## C2 — Texture / palette memory errors are silently discarded

Severity:

> **CRITICAL — invalid memory can render silently instead of faulting**

Current sampling lambdas call operations such as:

```text
src_view.read_raw(...)
src_view.read_rgba(...)
memory_.read32(palette...)
```

without checking their return status.

If:

- source rectangle exceeds resource bounds;
- command stride points outside allocation;
- palette address is invalid;
- a bilinear neighbor is not addressable;

the Golden can continue using zero/default color instead of returning the expected memory/address fault.

Required correction:

- every architectural memory read must propagate failure;
- sampler APIs should return `ExecResult + color`, `optional/error`, or equivalent;
- bilinear must fail if any required neighbor fetch fails after address-mode mapping;
- palette address calculation must use wide arithmetic and detect overflow;
- add directed negative tests.

Tile mode must not be built on a Golden that hides bad memory accesses.

---

## C3 — BLIT_EXT clipping is effectively always enabled

Severity:

> **HIGH — command-state semantics**

The current executor uses:

```text
if (CLIP_EN || has_ext)
    apply clip fields
```

But BLIT_EXT necessarily has an extension.

Therefore a BLIT_EXT command applies extension clip fields even when:

```text
CLIP_EN = 0
```

The builder also forces:

```text
clip_en = true
```

inside `make_blit_ext_cmd()`.

This conflates:

```text
extension exists
```

with:

```text
clip feature enabled
```

Required correction:

- `H_EXT_VALID` and `CLIP_EN` are independent concepts;
- BLIT_EXT requires the extension for UV, but clip is applied only when `CLIP_EN=1`;
- `make_blit_ext_cmd()` must not force Clip unless explicitly requested;
- test BLIT_EXT scale with Clip disabled;
- test identical extension clip words produce no effect when `CLIP_EN=0`.

---

## C4 — BLIT_EXT accepts affine cross-terms in non-Strict mode

Severity:

> **HIGH — ISA/front-end boundary**

The frozen architecture separates:

```text
BLIT_EXT
→ axis-aligned scale / flip

AFFINE_BLIT
→ full UV matrix
```

Current decode rejects:

```text
DV_DX != 0
DU_DY != 0
```

only when `H_STRICT=1`.

In non-Strict mode, BLIT_EXT can therefore become an affine renderer.

This erodes the front-end contract and makes later hardware comparison ambiguous.

Required correction:

> BLIT_EXT axis-alignment restriction is architectural, not merely a Reserved-field Strict check.

Reject non-axis BLIT_EXT regardless of `H_STRICT`.

Full affine remains for `AFFINE_BLIT`.

---

## C5 — SurfaceView stride/allocation validation is incomplete

Severity:

> **HIGH — command authority without safe validation**

Command stride/format are now used, which is good.

But the executor does not yet robustly validate that the command-defined view is legal.

The current destination stride check is limited and can allow row overlap or malformed views.

Required correction:

For a declared resource/view, validate at least:

```text
BPP(format) valid
stride >= logical row width * BPP
last addressed byte <= registered allocation
base + address arithmetic no overflow
```

Define whether the logical width is the registered resource width or a narrower explicitly modeled surface width and use one consistent rule.

Apply to source and destination.

Tests must prove:

- padded stride works;
- too-small stride faults;
- huge stride crossing allocation faults;
- exact-last-byte access works.

---

## C6 — Mutation-authority test contains tautological assertions

Severity:

> **CRITICAL — verification integrity**

The current mutation test contains checks equivalent to:

```text
EXPECT_TRUE(!st2.ok || st2.ok)
```

and:

```text
EXPECT_TRUE(got != expected || true)
```

These conditions are always true.

Therefore the test does **not** prove the command field is authoritative.

This violates the purpose of the mutation suite and the project test-integrity rule.

Required correction:

- remove all tautological assertions;
- every mutation must have a concrete expected behavior/fault/output;
- run a static grep/check in the rework task for obvious patterns such as:
  - `|| true`
  - `&& false`
  - `x || !x`
- REVIEW report must explicitly list the expected result for each mutation.

## C7 — Differential random verification does not satisfy Stage-003 scope

Severity:

> **HIGH — verification completeness**

The implemented `golden_test_random_diff` independently checks pixels, which is an improvement over Stage 002.

But it currently covers essentially:

```text
FILL COPY RGB565
BLIT COPY RGB565
```

The Stage-003 task required multiple suites including:

- Stage-002 blend/key subset;
- nearest scaling;
- clipping;
- Indexed8/Palette;
- bilinear.

Those suites are absent.

Required correction:

Create independent/reference oracles for:

```text
Q1 core + ColorKey + StraightAlpha + Additive
Q2 nearest scaling
Q3 clip
Q4 Indexed8 + palette
Q5 bilinear
```

Each suite must compare final pixels, not just successful execution.

## C8 — Several headline features are validated only by self-generated fixtures

Severity:

> **HIGH — oracle independence**

Fixtures are valuable permanent regressions, but:

```text
current Golden implementation
→ generate golden_fb.raw
→ later current Golden implementation compared to golden_fb.raw
```

does not independently prove the initial reference was correct.

This is especially insufficient for:

- Bilinear;
- Indexed8 Bilinear;
- Premultiplied Alpha;
- Dither;
- Color Mod;
- Repeat addressing.

Required correction:

Each mathematically nontrivial feature needs at least one directed test whose expected value is:

- hand-derived from the frozen formula; or
- computed by a deliberately independent small reference implementation.

Fixtures remain as full-frame regression artifacts after correctness has been independently established.

## C9 — Extension is fetched before header validation

Severity:

> **MEDIUM/HIGH — fault priority and architectural behavior**

`execute_command()` checks `H_EXT_VALID` and reads 64 bytes from `EXT_PTR` before the command header is fully validated.

A malformed command can therefore produce:

```text
MEMORY_ERROR
```

from extension fetch before the decoder has a chance to produce:

```text
BAD_VERSION
BAD_LENGTH
BAD_EXT_PTR
...
```

Required correction:

Use two-phase processing:

```text
decode / validate base header
→ validate EXT_PTR syntax/alignment
→ fetch extension
→ validate extension
→ decode draw payload
```

Define and test fault priority.

No invalid pointer should be dereferenced merely to discover that the header was already invalid.

---

## C10 — Extension Reserved-field Strict behavior needs correction

Severity:

> **MEDIUM — Strict semantics**

The decoder currently faults nonzero extension reserved words unconditionally.

Project ISA principle says Reserved-nonzero faults are a Strict-mode behavior.

Required correction:

- exact extension Reserved semantics must follow Command ISA;
- in Strict mode: fault as specified;
- in non-Strict mode: ignore only where the frozen ISA says it may be ignored;
- add paired tests.

Do not generalize non-Strict behavior without checking the spec.

---

## C11 — BLIT_EXT + Flip combination is not demonstrated and may be ignored

Severity:

> **MEDIUM/HIGH — feature composition**

Regular BLIT adjusts UV for `FLIP_X/Y`.

BLIT_EXT consumes explicit UV coefficients, but current code does not clearly define how the Flip flags combine with those coefficients.

Stage 003 claims:

```text
Scaling + Flip
```

as part of the feature-complete sprite path, but the directed suite only proves a basic fast-BLIT flip case.

Required correction:

Choose and document the frozen semantic implementation:

- either Flip flags transform the BLIT_EXT mapping; or
- the driver must encode flip in coefficients and the flags are rejected/ignored according to spec.

Do not silently accept a flag with no effect.

Test:

```text
scaled + flip X
scaled + flip Y
scaled + flip XY
```

---

## C12 — Q16 / source-coordinate upper boundary can invoke unsafe behavior

Severity:

> **MEDIUM — numeric robustness**

`SRC_X/Y` are uint16, while UV is signed Q16.16.

The fast BLIT path forms Q16 coordinates from source origin.

Values at/above 32768 require careful treatment because:

```text
32768 << 16
```

does not fit signed Q16.16.

The current parser correctly recognizes `SRC_X=32768`, but parser correctness alone does not make execution safe.

Required correction:

- remove any signed-shift UB;
- define executable behavior according to the platform's frozen maximum surface dimensions/capabilities;
- if such source origins are outside supported GPU dimensions, reject explicitly and deterministically;
- otherwise provide an addressing path that does not overflow Q16;
- add boundary tests.

Also verify `nearest_index_q16()` at the positive Q16 boundary.

---

## C13 — FILL + extension/Clip state needs explicit semantics

Severity:

> **MEDIUM**

FILL returns from decode before the common extension-loading path.

Therefore a FILL command carrying Clip Extension state can fail to consume the real clip descriptor and may use defaults.

Required correction:

Either:

1. support FILL + Draw2D Clip Extension correctly through the common extension path; or
2. if the frozen ISA explicitly excludes it, reject it with the correct fault.

Do not silently ignore an enabled Clip Extension.

---

## C14 — No-Clip target-bound behavior must be made explicit

Severity:

> **MEDIUM — Golden/RTL consistency**

The executor currently intersects rendering with render-target bounds even when explicit Clip is disabled.

The command ISA notes that negative/outside placement should use Clip Extension for defined clipping behavior.

Before Tile implementation, define one exact Golden rule from the authoritative specs:

```text
no Clip + fully in bounds
no Clip + partially out of bounds
Clip enabled + partially out of bounds
```

If the specs are insufficient, raise a `DESIGN_QUESTION` and update the specification before implementing Tile.

Immediate and Tile must later use the same rule.

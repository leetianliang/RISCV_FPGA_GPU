```text

→ decode / normalized Draw2DState
```

# 3. Mandatory Findings for Stage 003 Correction Block 0

The following issues do not require a new architecture, but they must be corrected before BLIT_EXT / Scaling / Tile work builds on top of Stage 002.

---

## B1 — Command stride/format fields are decoded but not authoritative during execution

Severity:

> **HIGH — executable-specification correctness**

`Draw2DState` correctly contains:

```text
SRC_STRIDE
DST_STRIDE
SRC_FORMAT
DST_FORMAT
```

However `GoldenGPU::execute_draw()` obtains registered `SurfaceDesc` objects and performs actual reads/writes using the registered surface's:

```text
stride
format
```

rather than the command's decoded stride/format.

Therefore a binary command can be mutated so that:

```text
command SRC_STRIDE != registered source stride
```

or:

```text
command SRC_FORMAT != registered source format
```

and the renderer can still use the harness metadata.

That violates the Golden architecture goal:

> the binary Command ISA must be the architectural authority.

Required correction:

1. Harness/registry metadata may provide:
   - backing memory;
   - resource width/height;
   - allocation bounds.
2. Command fields must provide:
   - stride;
   - pixel format;
   - source/destination addressing semantics.
3. Construct execution `SurfaceView` / equivalent from decoded command state.
4. Validate it against registered memory/resource bounds.
5. Add mutation tests proving that changing command stride/format either changes addressing correctly or faults; it must not be ignored.

This correction must happen before BLIT_EXT.

---

## B2 — `SRC_XY` is decoded as signed but the ISA defines it as unsigned 16-bit

Severity:

> **HIGH — ISA mismatch**

Current decode uses signed 16-bit unpacking for source X/Y and the builder stores source coordinates through a signed helper.

The Command ISA freezes:

```text
SRC_X : uint16
SRC_Y : uint16
DST_X : int16
DST_Y : int16
```

Required correction:

- `Draw2DState.src_x/src_y` become unsigned semantic values;
- decode with `unpack_u16_*`;
- command builders use unsigned source-coordinate packing;
- retain signed destination coordinates;
- tests must cover source coordinates around:
  - 0;
  - 32767;
  - 32768;
  - 65535 where resource bounds allow validation without huge allocation;
- parser-level tests must at least prove `0x8000` decodes as 32768, not -32768.

---

## B4 — Valid Stage-001 regression tests were removed/weakened

Severity:

> **HIGH — verification integrity**

Stage 001 had directed FILL coverage including:

- 1×1;
- interior;
- full surface;
- overlap/later-wins;
- zero width;
- zero height;
- non-tight stride;
- color set;
- ignored FILL fields;
- invalid header/no framebuffer modification.

Stage 002 replaced that suite with a substantially smaller FILL test set.

Similarly, some Stage-001 arithmetic directed cases were removed while refactoring.

This conflicts with the project test-integrity rule:

> do not delete valid regression coverage merely because the implementation was refactored.

Required correction:

- restore all Stage-001 behavioral coverage, or replace each removed test with an explicitly equivalent/better test;
- maintain a regression mapping table in REPORT_003;
- future stages must be monotonically non-decreasing in required behavioral coverage unless a specification changes.

---

## B5 — Stage-002 random regression does not verify output correctness

Severity:

> **MEDIUM/HIGH — verification quality**

The deterministic random test currently:

1. generates commands;
2. calls `execute_stream`;
3. passes if no fault occurs.

It does not compare final framebuffer content against an independent reference or strong invariant.

A renderer can therefore produce incorrect pixels and still pass the random suite.

Required correction:

Implement at least one of:

### Preferred
A deliberately simple independent scalar test renderer for the Stage-002 subset.

or:

### Minimum
Strong per-command/frame invariants independent of production helpers.

The random test must compare actual pixel output, not only execution success.

---

## B6 — Reserved encoding values are not fully distinguished from valid-but-unsupported features

Severity:

> **MEDIUM — fault semantics**

Examples in current decoder:

- `INDEX8` is a defined source format but currently unsupported → `UNSUPPORTED_FEATURE` is appropriate.
- source formats `0x4..0xF` are reserved → should be `BAD_FORMAT`, not generic unsupported.
- `BILINEAR` is defined but currently unsupported → `UNSUPPORTED_FEATURE`.
- filter values `0x2..0x3` are reserved → should be `BAD_FILTER`.
- blend values `PREMULT/MULTIPLY/XOR` are defined but unsupported → `UNSUPPORTED_FEATURE`.
- blend values `0x6..0xF` are reserved → should be `BAD_BLEND`.
- reserved address-mode encodings must be validated once address modes become active.

Required correction:

Create reusable enum classification:

```text
defined + supported
defined + unsupported
reserved/invalid
```

and test it.

---

## B7 — XRGB8888 write semantics violate Pixel Arithmetic V0.1

Severity:

> **MEDIUM — format correctness**

Pixel Arithmetic V0.1 freezes XRGB writes as:

```text
0xFFRRGGBB
```

The current `Surface::write_pixel()` writes the X byte as `0x00`.

Even though Stage 002 formally requires XRGB primarily as a source, the generic Surface implementation is already exposed and should not encode incorrect behavior.

Required correction:

- write X=0xFF;
- add exact LE byte tests.

---

## B8 — `round_div_signed` is not fully overflow-safe yet

Severity:

> **MEDIUM — reference arithmetic robustness**

The negative `INT64_MIN` case with denominator 2 no longer performs direct signed negation, but two edge risks remain:

- positive path can overflow in `num + den/2`;
- negative path can still encounter an unrepresentable intermediate/result around `INT64_MIN / 1`.

The current boundary test is also partly vacuous because it compares the function against another call with the same numeric input.

Required correction:

- implement quotient/remainder based round-to-nearest, ties-away-from-zero without overflow-prone absolute-value/add-half arithmetic;
- test against explicit expected constants;
- include:
  - `INT64_MIN / 1`;
  - `INT64_MIN / 2`;
  - `INT64_MAX / 1`;
  - near-half cases;
  - positive/negative ties.

---

## B9 — Command/fixture test matrix does not cover all requested Stage-002 stride/state cases

Severity:

> **MEDIUM — acceptance coverage**

The task requested specific non-tight source stride and non-tight destination stride BLIT tests and a wider alpha boundary matrix.

Current tests cover useful BLIT cases, but not the complete requested acceptance matrix.

This matters especially because B1 means command stride fields can currently be ignored without tests noticing.

Required correction:

Add explicit tests for:

- source stride padding;
- destination stride padding;
- mutation of command stride independent from harness metadata;
- Alpha effective values 0, 1, 127, 128, 254, 255;
- Global × Pixel Alpha staged rounding;
- no-write-on-validation-fault where validation occurs before rendering.

## 1. Scope

## 2. Passed items

- First real architectural path exists: `GpuCmd64 -> decode -> FILL -> Surface -> MemoryImage -> RAW framebuffer`.
- Scalar arithmetic implementation matches the written RGB565/DIV255/MUL8/Q16/LERP formulas and is intentionally easy to audit.
- Exhaustive RGB565, DIV255 and MUL8 tests are present; directed Q16/LERP tests are present.
- `MemoryImage` uses regions rather than a 4 GiB flat allocation.
- RGB565 reads/writes go through the memory abstraction.
- FILL implements half-open rectangles, zero-size no-op, COPY and RGB565 quantization.
- CMake/CTest now builds real C++20 targets; the Stage report records 8/8 CTest PASS.

The Stage-001 functional milestone is therefore accepted.

## 3. Mandatory corrective actions

These do not require architecture redesign, but must be completed before Stage-002 feature work proceeds.

### A1 — Golden reference fixture is auto-regenerated by normal build — HIGH

Current CMake declares checked-in `fill_basic` expected files as outputs of an `ALL` custom target. A changed implementation can therefore regenerate its own `golden_fb.raw` and then compare against that rewritten oracle.

Required:
- ordinary configure/build/CTest must never overwrite checked-in reference vectors;
- reference regeneration must be explicit and opt-in;
- current-run outputs belong in the build tree;
- expected-reference changes must appear as intentional Git diffs.

### A2 — Command binary I/O is host-endian dependent — MEDIUM

The CLI currently writes/reads the host memory representation of `std::array<uint32_t,16>` using raw memory operations. The ISA binary format is explicitly little-endian.

Required:
- explicit `serialize_cmd_le()` / `deserialize_cmd_le()` helpers;
- byte-shift implementation, not host-object memory layout;
- known-byte and 64B round-trip tests;
- all binary paths use these helpers.

### A3 — `FaultCode` numeric values diverge from the frozen Register Map — MEDIUM

The current enum omits `BAD_RING_CONFIG`, shifting subsequent values. Required: synchronize the complete frozen V0.1 table, with representative static/unit assertions including `BAD_RECT=0x000D`, `BAD_RING_CONFIG=0x000E`, `BAD_TILE_CONFIG=0x000F`, `MEMORY_ERROR=0x0013`, `BAD_ADDRESS=0x001B`.

### A4 — Strict-mode rules are applied unconditionally in places — MEDIUM

The ISA defines some Reserved/parameter checks as `H_STRICT` dependent. Current decode path faults some such states regardless of `H_STRICT`.

Required: implement exact strict/non-strict behavior and add paired tests.

### A5 — Defined-but-unimplemented opcode is conflated with `BAD_OPCODE` — MEDIUM

DRAW_2D defines `FILL_RECT=0x00`, `BLIT=0x01`, `BLIT_EXT=0x02`, `TILE_FRAME=0x10`. Current decoder treats every non-FILL opcode as bad.

Required:
- known + implemented -> execute;
- known + not implemented -> `UNSUPPORTED_FEATURE`;
- reserved/undefined -> `BAD_OPCODE`.

### A6 — 32-bit memory-region end is not fully enforced — MEDIUM

`register_region()` must reject half-open ranges extending beyond `0x1_0000_0000`. Add boundary tests near `0xFFFFFFFF`.

### A7 — `OUT_OF_RANGE` and `UNMAPPED` are not distinguished — MEDIUM

Required semantics:
- `UNMAPPED`: start address is in no region;
- `OUT_OF_RANGE`: start address is in a region but requested access crosses its end.

Apply to scalar and block accesses and test both.

### A8 — `round_div_signed` has an integer-boundary UB hazard — LOW/MEDIUM

The negative path evaluates `-num`, which overflows for `INT64_MIN`. Replace with overflow-safe quotient/remainder logic while preserving ties-away-from-zero semantics.

### A9 — `fill_basic` manifest contains the wrong base value — LOW

Fixture uses `0x10000`, but manifest records decimal `40960`. Generate metadata from the actual fixture constants.

### A10 — Actual HEAD adds an unreported Pillow dependency — LOW

The post-report preview script imports `PIL`. Stage 001 explicitly avoided third-party dependencies. Remove it, replace it with a standard-library-only preview path, or defer visualization dependencies to a later authorized stage. It must not be a hidden Golden build/test dependency.

### A11 — `model/golden/README.md` is stale — LOW

It still states that compiled Golden implementation has not started. Update after the correction block.

## 4. Decision

# **PASS WITH ACTIONS**

The architecture and functional FILL milestone are sound enough to continue. The issues are verification-integrity, protocol-classification, serialization and boundary-hardening issues rather than architectural failures.

Stage 002 may start **conditionally**: its Correction Block 0 must be completed and green before any new BLIT/Alpha feature implementation begins. No extra formal review is needed after that correction block unless a blocker/design question appears; submit one combined Stage-002 report at the end.

## 目标与保留项

交付一个真实可玩的、可连续滚动的 Power Test Area 样板区，让工程师、机械敌人、工业环境和基础战斗反馈形成统一画面。

保留 Application 1、独立 Application 2、Common Graphics API、4096×4096 世界、128×128 MapTile 网格、32×32 MapTile、世界坐标模拟、相机跟随与可见区剔除。只使用既有 GPU 绘制语义。

本轮以现有 640×360 interactive 为逻辑画面基准；同时查看原生尺寸与 2 倍窗口显示。2 倍展示不能标注为原生 720p 渲染性能。暂不扩展 Boss、六武器、碰撞墙体、存档等原任务外功能。

## R2-01 正确性修复

- 玩家、敌人、透明道具明确选择 StraightAlpha；保留地面的 Copy 和必要 FX 的 AddSat。
- 慢速敌人保留位移小数或整数余量，消除斜向零步进；替换逐距离循环求平方根，保持确定性。
- assetc 默认只读验证，检测缺失文件、字节/哈希/清单差异并返回失败；显式 update 才写输出。
- 不修改现有有效测试期望；为每个修复增加对应回归。

验收：透明像素不抹掉背景，半透明像素符合冻结算术；红蓝两像素经过生产后端显示正确；两类慢敌人在四象限斜向都持续接近玩家；验证失败不改任何受检文件。Immediate/Tile32 对对应测试场景一致。

## R2-02 重新处理最小素材集

- 逐对象核对裁框。删除统一 trim_bottom 百分比；完整提取身体，排除展示标签。
- 等比缩放到固定画布，统一动画锚点，不把不同宽高比直接拉满同一方形。
- 优先处理 Engineer 四向/idle、Drone/Crawler/Tank 两帧、Pulse Shot、XP、spark/explosion、完整地面和至少六种实际设施道具。
- 地面明确区分安静底板、低频变化、通风格/管线、警戒/标识，检视边缘拼接；达到原任务至少八块地面的要求，但不均匀随机铺满所有种类。
- 基础 HUD 所需 UI 单独裁剪。原任务要求的其余候选逐项记录完成状态，不能以最小集代替 Block A 全量要求。
- 联系表展示名称、大小、格式、锚点和原尺寸/放大预览，并在深浅背景上检视透明边缘。

验收：一个精灵只有一个对象；角色靴子和头部完整；帧间主体尺度与脚底位置稳定；地面无跨格误裁；联系表可直接判断各素材用途。

## R2-03 设施样板区

在大世界中设计一段连续空间，至少能跨越一个视口宽度和一个视口高度，滚动后仍有清晰的设备区、通道和战斗区域关系。

布局建议：中央低对比战斗地面；边侧终端、设备柜、箱组与管线；有方向、有转角、有出口的警戒标识；少量青色设备光和红色告警灯。用设备的排列解释空间功能，避免把零散道具随机撒在整个 4096 世界。

视觉顺序：玩家橙色头盔/青色装备首先可辨；敌人红色传感器与轮廓其次；投射物/命中在发生时明显；基础地板保持安静。设备区允许丰富，主要移动区留白。

地面密度比例是调图参考，不是靠统计数字代替视觉验收。先只改样板区与连续扩展规则；不将整个游戏变成固定单屏。

## R2-04 基础战斗呈现

修复后的 Drone/Crawler/Tank 正常进场与追击；增强既有 Pulse Shot 的轮廓，接入短促命中火花和击杀爆炸，限制效果寿命。用已有资源及 Alpha/Additive 实现，不添加新像素语义。

基础 HUD 使用工业面板，展示真实 HP、计时、击杀和武器状态；技术字段默认不占主画面。尚未完成的 XP/升级机制不得在效果截图中伪装为可用。

验收截图包含玩家、三类敌人、Pulse Shot、至少一次命中/击杀反馈与设施地标。若使用专用确定性展示场景，必须标记测试场景，并另附正常流程截图；不得把拼贴概念图作为运行结果。
